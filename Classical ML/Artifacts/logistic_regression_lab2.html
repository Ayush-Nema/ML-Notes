Module 1 · What is a prediction?

Intuition

Imagine you are a teacher. A student tells you how many hours they studied. You could ask two different questions: “How many points will they score?” — the answer is a number. Or: “Will they pass?” — the answer is a category: yes or no.

The thing we measure and feed in (hours studied) is called a . The thing we want to predict (the score, or pass/fail) is the target, also called a . The model’s guess is the prediction.

Try it

What’s happening mathematically?

Score mode: the green line is the best straight line through the dots (found by least squares, explained in Module 2). Its output can be any number on a continuous scale.

Pass/fail mode: each student is either 0 (fail) or 1 (pass). A single number like “1.37 students passing” makes no sense, so instead we want the of passing — a number between 0 and 1. The dashed purple curve is a preview of a model we will build in Module 5; it was fitted to these same dots with real logistic regression.

We can already predict numbers with a straight line. How exactly does a line produce a prediction? Let’s look at linear regression properly.

Module 2 · Linear regression first

Intuition

Suppose each extra hour of study tends to add about the same number of points. That is a straight-line relationship, and a straight line is easy to write down:

ŷ = m·x + b

x is the input (hours), m is the slope (points gained per hour), b is the intercept (the line’s value at x = 0), and ŷ (“y-hat”) is the predicted value.

Try it

A residual is the vertical gap between an observed dot and the line: observed − predicted. A good model keeps those gaps small. Notice also that a line has no built-in ceiling or floor:

What’s happening mathematically? Mean squared error

To score a line with one number we square each residual (so over- and under-shoots both count and big misses count extra) and average them: MSE = (1/N) Σ (yᵢ − ŷᵢ)²

The least-squares fit button picks the m and b that make this MSE as small as possible for a straight line. (In Module 8 we will see a more general way to find best parameters: gradient descent.)

We have a method for predicting numbers. But what if the answer can only be yes or no?

Module 3 · Why a plain line struggles with yes/no answers

Intuition

Let’s try the obvious thing: code “fail” as 0 and “pass” as 1, then fit the same kind of straight line. A value like 0.7 can be read as “70% likely to pass”. But what should “1.4” or “−0.3” mean? Probabilities cannot be below 0 or above 1.

Right: what we want — a probability-like curve

Fair warning: a straight line can be used for 0/1 outcomes — that is called a linear probability model, and it is sometimes a reasonable quick tool. The issue is that ordinary linear regression does nothing to keep predictions inside [0, 1], and any non-flat line must eventually leave that range if you go far enough (use the button above). Its error assumptions also fit 0/1 outcomes poorly.

Challenge: can we keep the useful linear formula but squash its output into a valid probability?

Our straight line can produce numbers outside 0 and 1. Can we transform any score into a valid probability? We need a squashing function…

Module 4 · The sigmoid: turning scores into probabilities

Intuition

Think of a dimmer switch that can never be fully off or fully on. Feed it a score z (any real number, negative or positive). Very negative scores give “almost 0”, very positive scores give “almost 1”, and a score of exactly 0 gives the middle: 0.5. That squashing function is the (an analogy — the exact formula is below):

σ(z) = 1 / (1 + e^(−z))   where e ≈ 2.71828

Try it

Four facts, checked live

Experiment: where is the sigmoid sensitive?

Push the score up by 1 and see how much the probability moves. Start near 0, then far away.

What’s happening mathematically?

The slope of the sigmoid is σ′(z) = σ(z)(1 − σ(z)). It is largest (0.25) at z = 0 and shrinks toward 0 in the tails. That is “saturation”: far from 0, big changes in the score barely change the probability. This will matter when we talk about gradients.

Also: σ(−z) = 1 − σ(z) because e^z/(1+e^z) = 1 − 1/(1+e^z)… try the second card above with different z. For any finite z, σ(z) is strictly between 0 and 1 (never exactly equal to the endpoints mathematically; very extreme z are shown as 0.0000 or 1.0000 only because of rounding).

Now we have a way to turn scores into probabilities. What happens when we feed it the output of a linear model?

Module 5 · Building logistic regression

Intuition

Here is the whole idea, in two steps. It reuses the line from Module 2 but renames the pieces (m → w, “weight”):

Step 1 — linear score: z = w·x + b   Step 2 — squash: p = σ(z) = 1 / (1 + e^(−z))

Try it

Graph A — the linear score z Graph B — the probability p (same x-axis)

Weight w: its sign sets the direction (positive → probability rises with x; negative → falls) and its size sets the steepness. Bias b: the score when x = 0; changing it slides the curve sideways. Threshold: a separate setting that turns a probability into a class — more in Module 6.

Key idea: logistic regression is a linear model for the log-odds, followed by a nonlinear transformation into probability space.
What’s happening mathematically? Odds and log-odds

= p/(1−p) (e.g. p = 0.75 → odds 3 to 1). The (or “logit”) is ln(p/(1−p)). Solving p = σ(z) for z shows that z is exactly the log-odds. So the straight-line part of the model, z = wx + b, models log-odds linearly; probabilities themselves are not a straight line in x.

A logistic model outputs a probability, not an answer. How do we turn “0.73” into a yes or no?

Module 6 · From probability to a decision

Intuition

A spam filter does not say “spam”; it says “92% likely spam”. Someone must choose a : predict class 1 if p ≥ threshold, otherwise class 0. (Equality counts as class 1.) The threshold is a decision setting, not a model parameter — moving it never retrains the model.

What do TP, TN, FP, FN mean?
  • True positive (TP): predicted spam, really spam.
  • True negative (TN): predicted not spam, really not spam.
  • False positive (FP): predicted spam, but it was a good email (a false alarm).
  • False negative (FN): predicted not spam, but it was spam (a miss).

Accuracy = (TP+TN)/all. Precision = TP/(TP+FP): of the emails we flagged, how many were really spam. Recall = TP/(TP+FN): of all real spam, how much we caught. F1 = 2·P·R/(P+R). If a denominator is 0, the metric is undefined and we show N/A instead of a made-up number.

Teaching points. 0.5 is a common default, not a law: if a false alarm (a real email lost in spam) is worse than a miss, raise the threshold; if a miss is worse, lower it. Lowering the threshold generally flags more emails as spam, so recall tends to rise while precision may fall. Also: model probabilities are estimates; they are not automatically well-calibrated (a “0.8” may not come true 80% of the time). These 16 emails are a tiny illustration, not a proof.

We can calculate a probability once we know w and b. But how should we choose them?

Module 7 · How does logistic regression learn?

Intuition

Training means finding w and b so the model’s probabilities agree with the observed labels: high p where the label is 1, low p where it is 0. To search, we need a score for “how wrong are we?” — a . For one observation with label y and predicted probability p we use :

L = −[ y·ln(p) + (1−y)·ln(1−p) ]

Only one term is ever active: if y = 1 then L = −ln(p); if y = 0 then L = −ln(1−p).

The loss curve

Correct and confident → tiny loss. Confident but wrong → huge loss (the curve shoots up as p approaches the wrong end). Worked examples:

pLoss if y = 1: −ln(p)Loss if y = 0: −ln(1−p)
What’s happening mathematically? Why not squared error?

You can train a sigmoid model with squared error, and people do. But cross-entropy is the standard because it matches the maximum-likelihood idea (the negative log-likelihood of the labels), its loss surface for w and b is convex, and its gradient has the clean form (p − y)·x. With squared error, a confidently wrong prediction gives almost no gradient because the sigmoid is flat there. Try it (label y = 1):

Module 8 · Gradient descent: watch the model learn

Intuition

Picture standing on a foggy hill, wanting to reach the valley. You feel which way the ground slopes under your feet and take a small step downhill. The is that slope, the α is your step size, and repeating this is . (The hill is an analogy; the formulas below are the facts.)

zᵢ = w·xᵢ + b pᵢ = σ(zᵢ)
J(w,b) = −(1/N) Σ [ yᵢ ln pᵢ + (1−yᵢ) ln(1−pᵢ) ]
∂J/∂w = (1/N) Σ (pᵢ − yᵢ)·xᵢ ∂J/∂b = (1/N) Σ (pᵢ − yᵢ)
w ← w − α·∂J/∂w b ← b − α·∂J/∂b

Careful: if the classes can be perfectly separated, the loss keeps shrinking toward 0 only by making |w| larger and larger — there is no finite “best” w. Try the “Perfectly separable” dataset and keep training. With a learning rate that is too large, the loss can bounce or rise instead of falling; loss is not guaranteed to fall at every step.

Now we know why w and b settle where they do. Let’s look at what the final model decides — and then train our own.

Module 9 · The decision boundary

Intuition

The boundary is where the model switches its answer. With threshold t, class 1 is predicted when p ≥ t, which (since σ is increasing) is the same as w·x + b ≥ log( t/(1−t) ). For t = 0.5 the right side is 0, so the boundary is w·x + b = 0 → x = −b/w (when w ≠ 0).

The probability curve is a bendy S-shape, but the boundary is linear in the features: a single point for one feature, a straight line for two.

Common misconceptions

“Logistic regression predicts continuous values like linear regression.”

It predicts a probability for a binary outcome (a number in (0, 1)), which a threshold can turn into a class. Its target is categorical.

“It always outputs exactly 0 or 1.”

No — the raw output is a probability. Even σ(10) = , not 1. Only after applying a threshold do you get a hard 0 or 1.

“The sigmoid makes a curved decision boundary.”

The probability curve is curved, but the boundary w·x + b = c is linear in the features (a point in 1-D, a line in 2-D) for the standard model.

“0.5 is always the best threshold.”

It is a default. The best threshold depends on the costs of false positives vs false negatives and on class balance.

“Threshold and parameters are the same thing.”

Parameters (w, b) are learned by training. The threshold is chosen afterward and changing it does not retrain anything.

“Training accuracy tells us how it will do on new data.”

It only measures fit to data the model has seen. Use held-out data, and remember even that is an estimate.

“A coefficient is a fixed increase in probability.”

Actually a one-unit increase in x multiplies the odds by ew (holding other features fixed). The change in probability depends on where you start. Drag w and compare three starting probabilities (also: coefficients describe associations in the data, not causation):

Recap

Linear regression

x → m·x + b → a continuous number

Use when the target is a quantity (score, price, temperature).

Logistic regression

x → w·x + b → sigmoid → probability → threshold → class

Use when the target is a yes/no category and you want probabilities.
