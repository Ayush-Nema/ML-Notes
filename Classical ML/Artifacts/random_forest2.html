Random Forest: from one tree to a crowd of trees

A random forest is one of the most reliable “first choice” models for tabular data. It is built from a very simple idea: ask many slightly different decision trees and let them vote.

What you will be able to do after this lesson

  • Explain what a decision tree is and read one as a set of if–then rules.
  • Compute entropy, Gini impurity and information gain by hand, and understand how a tree picks its splits.
  • Diagnose overfitting and measure a model with accuracy, precision, recall, F1, cross-validation and OOB error.
  • Explain bagging and feature randomness, and why they reduce variance.
  • Train a forest on the real Iris dataset, read feature importances, and tune hyperparameters.
  • List the strengths, weaknesses, assumptions and validation steps of random forests.

Part 1 · Intuition

A tree is a flowchart of yes/no questions

Think of the game “20 questions”. Each question splits the possibilities in two, and after a few good questions you can name the answer. A decision tree is a flowchart that was learned from data to do exactly that.

Anatomy of a tree

  • Root node: the first question, asked about every example.
  • Internal node: a question about one feature, e.g. “Is Outlook = Sunny?” or “Is petal length ≤ 2.45?”.
  • Branch: one possible answer to the question.
  • Leaf: the end point; it outputs a prediction (a class, or an average for regression).
  • Depth: the longest chain of questions from root to a leaf.

Toy example 1 — “Should we play tennis?”

Fourteen past days were recorded. For each day we know the weather and whether we played. The tree below was learned from this table (you will learn how in the next sections).

Key ideaA tree is just a set of rules:
IF Outlook = Overcast THEN Play = Yes
IF Outlook = Sunny AND Humidity = High THEN Play = No
Each path from root to leaf is one rule. That is why trees are so easy to explain to non-experts.

Part 2 · How trees are created (1/3)

Which question should we ask first?

A good question separates the classes into pure groups: groups where almost everyone has the same label. We need a number that measures “how mixed” a group is.

Impurity: how mixed is a bag of marbles?

0.50fraction orange p
0.500Gini impurity
1.000Entropy (bits)

For a group S with K classes, let pk be the fraction of examples in class k. Two popular measures:

G(S)=1−∑k=1Kpk2(Gini impurity) H(S)=−∑k=1Kpklog2pk(Entropy)

Both are 0 for a perfectly pure group and largest when the classes are evenly mixed (for two classes: Gini = 0.5, entropy = 1 bit). Move the sliders to see the curves.

Information gain: how much did a question help?

A split sends nL examples left and nR right. The quality of the split is the weighted impurity of its two children, and the gain is how much impurity dropped:

I(S,q)=nLnG(SL)+nRnG(SR) Δ(S,q)=G(S)−I(S,q)

With entropy in place of G, Δ is the famous information gain used by ID3/C4.5. The tree picks the question q with the largest gain.

Gain of every feature at the root

ResultOutlook gives the biggest drop in impurity, so it becomes the root. Then the algorithm repeats the same procedure inside each branch. (Sunny → asks about Humidity; Rain → asks about Wind.)

The greedy recursive algorithm

  1. Start with all training data in the root node.
  2. For every feature j and every candidate threshold t (midpoints between consecutive sorted values) compute the weighted impurity of the two children.
  3. Pick the best pair and split the node in two:
    (j*,t*)=argminj,tI(S,j,t)
  4. Recurse on the left and right child.
  5. Stop when a node is pure, the depth limit is reached, there are too few samples to split, or no split improves impurity. Make it a leaf that predicts the majority class.
“Greedy” means short-sightedThe algorithm picks the best split right now without looking ahead. It is fast, but does not guarantee the globally best tree. A small change in the data can change the root split, so a whole tree can change. This instability matters later.

Regression trees

If the target is a number (house price, temperature) the leaf predicts the mean of its training targets and the impurity is the mean squared error around that mean:

MSE(S)=1|S|∑i∈S(yi−y¯)2

k-fold cross-validation

  
One test set can be lucky or unlucky. Cross-validation splits the data into k folds; each fold takes one turn as the test set while the model trains on the other k−1 folds:

  
ScoreCV=1k∑i=1kScorei

  

  
Random forests have a free validation setEach tree is trained on a bootstrap sample, so some rows are left out of that tree. Predicting those rows with only the trees that never saw them gives the out-of-bag (OOB) score, a built-in estimate of test performance. You will compute it in Part 6.







  
Part 6 · Random Forest

  
Many different trees, one vote

  
One tree is unstable. The fix: grow many trees, make each one see the data a bit differently, and combine their answers.


  
6.1 Why does a crowd beat an individual?

  

    
Suppose each “voter” is right with probability p and they vote independently. What is the chance the majority is right?

    

      
      
    

    
–P(majority is correct)

    
    
P=∑k>N/2N(Nk)pk(1−p)N−k

    
Mediocre voters become excellent as a group, but only if their mistakes are not all the same. Ten copies of the same tree vote identically and gain nothing. We need diverse trees. A random forest creates diversity in two ways:

  


  

    
① Bagging (bootstrap aggregating)
Each tree trains on a bootstrap sample: draw n rows with replacement from the n training rows.

    
② Random feature subsets
At every split, a tree may only consider a random subset of m out of p features (typical: m≈p for classification, p/3 for regression).

  


  
6.2 Bootstrap sampling — draw it

  

    

      
      

    
Each square is one training row. Purple = picked (number = how many times). Grey = never picked, i.e. out-of-bag for this tree.

    

    

      
–unique rows in bag

      
–out-of-bag rows

      
–average unique % (1000 draws)

    

    
The chance that a particular row is never picked in n draws:

    
(1−1n)n⟶e−1≈0.368

    
So each tree sees about 63.2% unique rows and leaves out about 36.8%. Those left-out rows are what makes the OOB score possible.

  


  
6.3 Why averaging reduces variance

  
Suppose each tree has prediction variance σ2 and the trees' predictions have pairwise correlation ρ. The variance of the average of B trees is:

  
Var(f¯)=ρσ2+1−ρBσ2

  

    

      
      
    

    
–Var of forest (σ² = 1)

    
    
Adding trees kills the second term, but the first term ρσ2 remains. That is why decorrelating trees (random feature subsets!) is just as important as adding more of them.

Part 7 · How a Random Forest is built

  
The recipe: bag the data, shuffle the features, vote

  
You now know why a crowd of different trees beats one tree. This section shows exactly how the crowd is created, step by step, starting with the first ingredient: bagging.


  
7.1 Bagging = Bootstrap + aggregating

  

    
🧠 The intuition

    
Imagine 100 students preparing for the same exam. Each gets a different photocopy of the textbook: some pages are copied twice, some are missing. Every student studies alone and writes an answer sheet. The final answer is whatever most students wrote. Each student is a bit wrong in their own way, but their mistakes differ, so the majority is more reliable than any one student.

    
That is bagging. The “students” are decision trees and the “photocopies” are bootstrap samples of the training data.

  

  
    
    
  1. Bootstrap: create B new training sets, each by drawing n rows with replacement from the original n rows.
    2. 
    
  2. Train independently: fit one model (here a deep decision tree) on each bootstrap set.
    3. 
    
  3. Aggregate: combine all predictions into one: a vote for classification, an average for regression.
    4. 
  

  

    Db*={(xi1,yi1),…,(xin,yin)},ij∼Uniform{1,…,n}(for each b=1,…,B)
    hb=Tree trained on Db*y^bag(x)=1B∑b=1Bhb(x)
  

  

    
What bagging fixes

      
The average of B trees has the same bias as one tree, since E[h¯]=E[hb], but a much lower variance. This is why we grow each tree deep (low bias) and let averaging remove the instability.

    
Who benefits from bagging?

      
Unstable learners change a lot when the data change slightly: deep decision trees, neural networks. They gain a lot.

      
Stable learners barely change: linear regression, k-NN with large k. They gain almost nothing.

  

  
Hard vote vs. soft vote
    Hard vote: each tree votes for one class; the most frequent class wins.

    Soft vote: each tree reports the class fractions in its leaf, pb(c∣x), and the forest averages them:
    P^(c∣x)=1B∑b=1Bpb(c∣x)y^=argmaxcP^(c∣x)
    scikit-learn uses the soft vote. Our demos use the simple hard vote.

7.3 Bagging alone is not enough: random feature subsets

  
If one feature is clearly the strongest, every bagged tree will put it at the root and build nearly the same tree, even though the bootstrap samples differ. The trees stay highly correlated (ρ is large), and from Part 6 we know that a large ρ limits how much averaging can help.

  
Random forest adds a second source of randomness: at every split of every tree, only m randomly chosen features (out of p) are allowed to compete. Strong features sometimes sit out, so weaker features get a chance, and the trees become different from one another.

7.5 The full recipe

  
INPUT : training set D with n rows and p features,
        number of trees B, features per split m
FOR b = 1 ... B:
    1. Draw a bootstrap sample D*_b  (n rows, with replacement)
    2. Grow a tree h_b on D*_b:
         at EVERY node:
           a. pick m features at random out of p
           b. find the best (feature, threshold) among those m
              (largest drop in Gini / entropy)
           c. split, then repeat on both children
         stop when a node is pure or too small   (no pruning)
    3. Remember which rows were NOT drawn (the out-of-bag rows)
PREDICT x : majority vote of h_1(x) ... h_B(x)     (regression: average)

  
The rows left out of Db* give a free validation score. For each training row i, only the trees that never saw it vote:

  

    y^ioob=mode{hb(xi):i∉Db*}Erroob=1n∑i=1n𝟙[y^ioob≠yi]
  

  
SummaryRandom forest = bagging + random feature subsets + deep unpruned trees + voting. Bootstrap and feature randomness make trees different, deep trees keep each one low-bias, and voting averages away the variance. In the next section you will train one on real data.

Part 9 · Intermediate

  
What did the forest learn, and how do we tune it?

  
8.1 Impurity-based importance (MDI)

  
Every time a feature is used for a split, it reduces impurity. Add up those reductions, weighted by how many samples reached the node, and average over trees:

  
Imp(j)=1B∑b=1B∑t∈Tb:feat(t)=jntNΔGt

  
8.2 Permutation importance

  
Shuffle one feature's column in the test set, breaking its link with the label, and measure how much accuracy drops. A big drop means the model really relied on that feature. It is less biased than MDI, which favours features with many distinct values.

Part 10 · Strengths and weaknesses

  
When should you reach for a random forest?

  
Click each card to expand the details.

  

    

      
✅ Merits

      
Strong accuracy out of the boxAveraging many decorrelated trees gives low variance without much tuning. Often a hard-to-beat baseline on tabular data.

      
Resistant to overfitting (as B grows)Adding more trees does not make the forest overfit more; the variance only decreases until it plateaus at ρσ2. (Individual deep trees may still memorise noise; the forest averages it out.)

      
No feature scaling neededSplits compare a feature to a threshold, so only the order of values matters. Standardising or log-transforming features does not change the splits.

      
Handles non-linear effects and interactionsThe tree structure naturally captures “if A is high and B is low” without you engineering interaction terms.

      
Mixed feature types, little preparationNumeric and (encoded) categorical features can coexist. Some implementations handle missing values natively.

      
Built-in validation and diagnosticsOOB score, feature importance and proximity measures come for free. Training parallelises easily because the trees are independent.

    

    

      
⚠️ Demerits

      
Less interpretable than a single treeYou can read one tree, but not 500. Importance plots and partial-dependence/SHAP help, yet the model is a “grey box”.

      
Cannot extrapolatePredictions are averages of training targets, so outside the training range a regression forest simply flatlines (see Part 11).

      
Memory and prediction timeHundreds of deep trees must be stored and traversed. It can be heavy for large models or low-latency edge devices.

      
Can be biased toward high-cardinality featuresMDI importance favours features with many unique values (e.g. IDs). Use permutation importance to double check.

      
Struggles with very sparse, high-dimensional dataFor text bag-of-words or wide sparse matrices, linear models often win. Images, audio and sequences are better served by deep learning.

      
Probabilities are not always calibratedVote fractions are rough probabilities, often too cautious near 0 and 1. Calibrate (Platt/isotonic) if you need trustworthy probabilities.

      
Imbalanced classes can hurtMajority voting favours the common class. Use class weights, resampling and threshold tuning, and judge with recall/F1, not accuracy.

Part 11 · Assumptions and sanity checks

  
What does a random forest assume?

  
Random forests are non-parametric: unlike linear regression they do not assume a linear relationship, normally distributed errors or constant variance. But they are not assumption-free.

  
Assumptions & what to check

  
1. Training data are independent and identically distributed (i.i.d.)Bootstrap sampling assumes rows are independent draws. Check: are there repeated measurements of the same person, patient, store or machine? If so, use grouped cross-validation so that the same entity is never in both train and test. For time series, use time-ordered splits.

  
2. Train and future data come from the same distributionIf tomorrow's data look different (drift), the learned splits no longer apply. Check: compare feature distributions of train vs new data; monitor performance after deployment.

  
3. The features contain signal; labels are reasonably accurateA forest cannot create information that is not there. Heavy label noise hurts, although averaging provides some robustness. Check: compare to a trivial baseline (majority class, mean); inspect mislabeled rows.

  
4. No data leakageFeatures that secretly contain the answer (e.g. “discharge status” when predicting hospital readmission) give amazing validation scores and useless real-world models. Check: unusually dominant importance for one feature; fit scalers/encoders inside cross-validation folds.

  
4b. Sufficient, representative samples for each classRare classes may never reach a leaf in large enough numbers. Check: class counts, per-class recall, stratified splits, class_weight.

  
5. Inputs are numeric (categoricals encoded) and missing values handledMost libraries require one-hot or ordinal encoding (and imputation) unless they support these natively. High-cardinality one-hot columns dilute the random feature subset.

  
What you do NOT need✔ no scaling or normalisation ✔ no linearity ✔ no normality ✔ no homoscedasticity ✔ outliers in features are tolerated (splits are rank-based). Outliers in the target still affect regression leaf means.

    Reproduce it in Python (scikit-learn)
    
  
    from sklearn.datasets import load_iris
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.metrics import classification_report

X, y = load_iris(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)

rf = RandomForestClassifier(
    n_estimators=200,      # B: number of trees
    max_features="sqrt",   # m: features tried per split
    min_samples_leaf=1,
    oob_score=True,        # free validation estimate
    n_jobs=-1, random_state=0,
).fit(X_tr, y_tr)

print("OOB accuracy :", rf.oob_score_)
print("Test accuracy:", rf.score(X_te, y_te))
print(classification_report(y_te, rf.predict(X_te)))
print("5-fold CV    :", cross_val_score(rf, X, y, cv=5).mean())
print("Importances  :", rf.feature_importances_)
