Decision Trees

A hands-on, click-everything guide for first-time machine-learning learners. We start with a game of 20 Questions and finish by training, testing and breaking a real tree.

Part 1

The big idea: 20 Questions with data

A decision tree is a flowchart of yes/no questions that ends in a prediction. The twist in machine learning: we don't write the questions ourselves — the algorithm discovers the best ones from examples.

🍎 Try it: guess the fruit

Think of a banana, lemon, orange or apple and answer the questions honestly. Watch the path light up.

🧾 A tree is just if/else code

if color == "yellow":
    if shape == "long and curved":
        return "Banana"
    else:
        return "Lemon"
else:
    if skin == "bumpy":
        return "Orange"
    else:
        return "Apple"

Programmers write rules like this by hand. A decision-tree learner builds them automatically from a table of labelled examples.

🎯 Two flavours of tree

Classification tree — predicts a category (spam / not spam, species of flower, will the customer churn?).

Regression tree — predicts a number (house price, tomorrow's temperature). We visit this in Part 8.

Most of this guide uses classification — the ideas carry over almost unchanged.

Part 2

How does a tree pick a question? Purity!

A good question splits a mixed-up group into groups that are purer (more of one class). To compare questions we need a number that says how mixed a group is — that number is called impurity.

📐 The math, with plain-English meaning

Notation. A node holds N training examples spread over K classes. Class k has nk examples, so its share of the node is pk = nk / N. A split sends the examples into child nodes j = 1…m, where child j holds Nj examples. Σ means “add up over all classes (or all children)”.

Gini index

G = 1 − Σk pk2

Meaning: the chance that two examples picked at random from the node belong to different classes. Pure node → 0. More mixing → bigger.

Range: 0 to 1 − 1/K (0.5 for two classes).
Example: 9 Yes / 5 No → 1 − (0.643² + 0.357²) = 0.459

Entropy

H = − Σk pk · log2( pk )

Meaning: the average “surprise”, measured in bits — roughly how many yes/no questions you would need to ask to learn the class of a random example. Pure node → 0 bits.

Range: 0 to log2K (1 bit for two classes). By convention 0·log20 = 0.
Example: 9 Yes / 5 No → 0.940

Information gain

IG = I(parent) − Σj ( Nj / N ) · I(childj)

Meaning: how much impurity (uncertainty) the question removes. I is either Gini or entropy; the sum is the weighted average impurity of the children, where a bigger child counts for more.

Range: never negative; 0 = question didn't help; max = I(parent) (children perfectly pure).
Example: splitting the tennis data on Outlook → 0.9403 − 0.6935 ≈ 0.247

How they fit together: (1) measure the parent's impurity with G or H, (2) measure each child's impurity, (3) take the size-weighted average of the children, (4) subtract. The tree evaluates this for every candidate question and picks the one with the largest gain. When I = entropy this is called information gain (ID3, C4.5); when I = Gini it is the Gini decrease used by CART (scikit-learn's default).

For regression trees, I becomes the variance (mean squared error) of the target values in the node: Var = (1/N) Σ (yi − ȳ)2.

🔵🟠 Experiment 1: measure messiness

A node contains 20 items of class A (teal) or B (amber). Slide to change the mix.

Both measures are 0 when the node is pure and largest at a 50/50 mix. Gini peaks at 0.5, entropy at 1.0 — different scale, same idea. In practice they usually give very similar trees.

✂️ Experiment 2: score a split

A parent node has 10 A and 10 B. A question sends some items left and the rest right. How much purer do the children get?

Information gain = impurity of the parent − weighted average impurity of the children. The tree tries every possible question and picks the one with the biggest gain. (Weighted = a child with more items counts more.)

Part 4

The algorithm in plain English

Every tree learner (ID3, C4.5, CART — the one in scikit-learn) follows the same recursive recipe.

  1. Start with all training examples in one node (the root).
  2. Check stop rules. Is the node pure? Is it too deep? Too few samples? If yes → make it a leaf that predicts the majority class and stop.
  3. Try every candidate question on every feature and compute the information gain of each.
  4. Keep the best question and split the examples into child nodes.
  5. Repeat steps 2–4 on each child (this is called recursion) until every branch ends in a leaf.

Greedy: at each node the tree picks the locally best question without looking ahead. Fast, but not guaranteed to find the best possible tree overall.

Left alone, a tree keeps splitting until every training example is classified perfectly — which is usually memorising, not learning. Stop rules (hyperparameters) hold it back. See Part 7.

📏 How are questions on numbers chosen?

For a numeric feature like petal length, the tree can't ask "is it 1.4? is it 1.5?…" forever. Instead it sorts the values, takes the midpoint between neighbouring values as a candidate threshold, and scores each with the same impurity trick: "is petal length ≤ t?"

Max depth max_depth — how many questions in a row?
What it is

A cap on the number of levels below the root. Depth 1 is a single question (a “decision stump”); depth 3 means no path asks more than 3 questions, so there are at most 2³ = 8 leaves. The right end of the slider means no limit (None): the tree keeps growing until its leaves are pure or can't be split.

What to expect
▲ Increase
More leaves and finer boundaries. Training accuracy climbs toward 100%. Test accuracy improves at first, then levels off or drops (overfitting). Once every leaf is pure the tree stops by itself, so raising the slider further changes nothing.
▼ Decrease
A smaller tree that is easy to explain. Go too low and it underfits: both training and test scores are poor because the tree can't ask enough questions.

Sepal only63 / 63 (2)78 / 73 (4)82 / 75 (8)86 / 74 (14)95 / 70 (36)

Reading it: with petal features depth 2–3 is already enough and extra depth adds nothing. With sepal features, training accuracy keeps rising (82% → 95%) while test accuracy falls (75% → 70%) and the leaf count explodes from 8 to 36 — textbook overfitting.

Rule of thumb: start at 3–5 and pick the smallest depth where the test score stops improving.

Min samples per leaf min_samples_leaf — how small may a leaf be?
What it is

A split is only allowed if both children keep at least N training examples. A node therefore needs at least 2N examples before it can split at all. This stops the tree from carving a leaf around one or two unusual flowers (outliers and noise).

What to expect
▲ Increase
Fewer, bigger leaves and smoother, simpler boundaries. Training accuracy drops; test accuracy usually stays about the same (or improves a little on noisy data). Too high and the tree underfits.
▼ Decrease
At 1, every split is allowed, so the tree can isolate single examples — it memorises the training set, noise included.

Reading it: on sepal data, going from N = 1 to N = 5 makes the tree three times smaller while test accuracy stays at 70% — the extra leaves were only fitting noise. A simpler tree with the same test score is the better model.

Works together with max depth: a branch stops as soon as either limit is reached. Rule of thumb: 1–5 for small datasets; for large ones, about 1–5% of the rows.

Impurity measure criterion — Gini or entropy?
What it is

The formula that scores how mixed a node is when comparing candidate questions (see Part 2): Gini = 1 − Σp², entropy = −Σp·log₂p. scikit-learn's options are "gini" (default), "entropy" and "log_loss" (same as entropy).

What to expect

This is not a complexity knob, and it rarely matters. Both measures are 0 for pure nodes and largest at a 50/50 mix, so they usually pick the same questions. Entropy punishes mixed nodes slightly harder and costs a logarithm per class, but the difference is tiny.

Features the tree may use max_features — which columns can it ask about?
What it is

In the lab you choose which measurements the tree may use (2 or all 4). In scikit-learn the related hyperparameter is max_features: how many randomly chosen features are examined at each split (default: all). Random Forests lean on this to make their trees different from one another.

What to expect
▲ More features / more candidates
More chances to find a strong question, so higher accuracy if the extra features carry information. Training is slower. Useless features are mostly ignored (sepal importance is 0% when petal features are available), but a deep tree can still latch onto one if it happens to fit noise.
▼ Fewer features / fewer candidates
Faster and more varied trees, but the tree may never see the best question. With only sepal measurements the best test score is about 75%, versus about 94% with petal measurements.

Tip: a 2-feature setting lets you draw the decision regions; with 4 features the map shows a 2-D slice.

Test set size test_size — not a model hyperparameter, but it changes your readings
What it is

The share of flowers hidden from the tree and used only for grading. It does not change how the tree is built — it changes which flowers the tree learns from and how many it is graded on.

Rule of thumb: 20–30%, or use cross-validation when data is scarce.

Random split random_state — which flowers land in train vs test?
What it is

The random seed that shuffles the data before splitting (and breaks ties between equally good questions). You don't tune it; you use it to check how stable the result is.

What to expect

Same settings, different split → a somewhat different tree and score. With petal features at depth 3, test accuracy ranged from 89% to 100% across 30 seeds. The root question was always on petal length, but its threshold varied between ≤ 2.35, ≤ 2.45 and ≤ 2.60: any cut between the setosa flowers and the rest separates them equally well, so the tree takes the midpoint between whichever neighbouring training flowers it happens to see.

Reading it: the structure is stable, the exact numbers wiggle — this is the high variance of a single tree (Part 7). Rule of thumb: fix a seed for reproducible demos, and report a cross-validation average instead of one lucky split.

Other hyperparameters you'll meet in scikit-learn
  • min_samples_split — a node needs at least this many examples to be considered for splitting (default 2). ▲ = simpler tree; min_samples_leaf is usually easier to reason about.
  • min_impurity_decrease — only split if the gain is at least this large. ▲ = fewer splits; a form of pre-pruning that skips questions that barely help.
  • max_leaf_nodes — grow best-first until the tree has this many leaves. ▲ = more complex.
  • ccp_alpha — strength of cost-complexity post-pruning: grow a big tree, then cut branches whose benefit is smaller than their complexity cost. ▲ = more branches removed, smaller tree.
  • class_weight — "balanced" gives rare classes more influence on the splits. Helps with imbalanced data: rare-class recall usually rises, with possibly more false alarms.

Part 6

Is the tree any good? Evaluating it

Training accuracy only tells us how well the tree memorised what it saw. The real question is: how will it do on flowers it has never seen? That's what the held-out test set is for.

🧮 Confusion matrix (test set)

Rows = the true species, columns = what the tree predicted. The diagonal (bold) holds the correct answers; every other cell is a specific kind of mistake.

🎯 Per-class report

accuracy = correct ÷ all
precision = of those I called X, how many really were X?
recall = of all real X, how many did I find?
F1 = balance of precision and recall

🔁 Cross-validation: a steadier score

One random split can be lucky or unlucky. k-fold cross-validation splits the data into k parts, trains on k−1 parts, tests on the remaining one, and rotates until every part has been the test set once.

Rule of thumb: if training accuracy ≫ test accuracy, you're overfitting. If both are low, you're underfitting (the tree is too simple). For regression trees we use error metrics such as MSE, MAE or R² instead of accuracy.

Part 7

Overfitting: when a tree memorises

A deep enough tree can carve out a tiny leaf for every odd training example — noise included. It scores perfectly on training data and badly on new data.

📈 Train vs. test accuracy as the tree grows

Each point is averaged over 15 random splits, using your current feature set, impurity measure, leaf size and test size. The shaded column is your current max depth.

🩹 How to fight overfitting

  • Pre-pruning: stop early — max_depth, min_samples_leaf, min_impurity_decrease. Try the sliders in the lab.
  • Post-pruning: grow a big tree, then cut off branches that don't earn their keep (cost-complexity pruning, ccp_alpha in scikit-learn).
  • More data or fewer noisy features.
  • Ensembles: average many trees — Random Forest, Gradient Boosting.

🎲 Instability test

Train on 8 different random splits with your current settings. Does the root question stay the same?

Big picture: a single tree has high variance — small changes in the data can change the tree a lot. A Random Forest trains hundreds of trees on random subsets of rows and features and lets them vote; the mistakes average out, usually giving much better accuracy at the cost of some interpretability.

Part 8 · Bonus

Regression trees: predicting numbers

Same recipe, two changes: leaves predict the average of their training targets, and "impurity" becomes the squared error (how far values are from their group's average). The result is a staircase-shaped prediction.

–train MSE
–test MSE
–leaves (steps)

The hidden truth is a smooth sine wave plus noise. Depth 1–2 is too simple (underfit); depth 10 chases every noisy dot (overfit: train error → 0 while test error rises again). Notice too that a regression tree can't predict outside the range it has seen — it just repeats its last step.

Part 9

Merits and demerits

👍 Merits

  • Easy to understand & explain. You can print the tree and show it to a non-technical stakeholder (a "white-box" model).
  • Little data preparation. No feature scaling or normalisation; mixed numeric and categorical features are fine.
  • Captures non-linear patterns and interactions (e.g. "humidity matters only if it's sunny") without you engineering them.
  • Built-in feature importance and automatic feature selection.
  • Fast predictions — just a handful of comparisons.
  • Handles both classification and regression, including multi-class problems.
  • Robust to outliers in the input features (splits depend on order, not magnitude).

👎 Demerits

  • Overfits easily when grown deep — needs pruning or depth limits.
  • Unstable (high variance). Small changes in the data can produce a very different tree.
  • Axis-aligned splits only. A diagonal boundary becomes an ugly staircase of many splits.
  • Greedy, not optimal. Choosing the best split now can miss a better tree overall.
  • Biased toward features with many distinct values (e.g. an ID column can look "perfect").
  • Struggles with imbalanced classes unless you re-weight them.
  • Regression trees can't extrapolate and give blocky, piecewise-constant predictions.

Take-away: use a single tree when explainability matters or as a quick baseline. When raw accuracy matters, reach for tree ensembles (Random Forest, XGBoost, LightGBM) — they are built from the same simple building block you just learned.

💻 Do it in Python (scikit-learn)

from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier, plot_tree

X, y = load_iris(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(
    X, y, test_size=0.3, stratify=y, random_state=0)

model = DecisionTreeClassifier(max_depth=3, criterion="gini", random_state=0)
model.fit(X_tr, y_tr)

print("train acc:", model.score(X_tr, y_tr))
print("test  acc:", model.score(X_te, y_te))
plot_tree(model, filled=True)
