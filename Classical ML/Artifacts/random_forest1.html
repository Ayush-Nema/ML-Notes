01 · Big idea · From intuition to intermediate

One tree can be noisy.
A forest finds the pattern.

A Random Forest combines lots of decision trees. Each tree sees a slightly different slice of the training problem; together, they vote or average to make a more stable prediction.

03 · Growing the tree

How does a tree learn which question to ask?

At a node, it tries candidate feature thresholds and chooses one that makes the child groups more useful for predicting the target.

1
Begin with the training rows at this node.

For example, 40 flowers with mixed species.

2
Propose candidate splits.

Petal length ≤ 2.45? Sepal width ≤ 3.1? Each candidate divides rows into left and right.

3
Score the split.

Measure the target impurity before and after the split. Prefer a larger reduction.

4
Repeat on each child.

Stop when a growth limit is reached: maximum depth, minimum rows per leaf, or no useful improvement.

CLASSIFICATION

Gini or entropy

These measure how mixed the class labels are in a node. Information gain is entropy before the split minus the weighted entropy afterward.

REGRESSION

Squared error reduction

Choose a split that reduces the within-node squared deviations of target values. Leaves predict a constant, often their target mean.

Greedy construction: most decision-tree implementations choose the best immediate split at each node. They do not search every possible complete tree, so the result is not guaranteed globally optimal.
04 · A little math, made visible

Quantify “mixed”: Gini impurity

For a node with class proportions pk, Gini measures the chance of a wrong label if we guessed according to that node’s class mix.

Gini formula

G=1−∑k=1Kpk2
pk is the fraction of class k in this node. Gini is 0 for a pure node.

For a binary node that is 50% Yes and 50% No:

G=1−(0.5)2−(0.5)2=0.5

For K classes, the maximum is 1 − 1/K when classes are equally represented.

06 · From one tree to many

Bagging: train separate trees, then combine them.

Each tree is a complete learner. It gets its own bootstrap sample, grows using ordinary tree-splitting rules, and makes a prediction for the same new case. The forest aggregates those predictions.

1
Draw a bootstrap dataset for Tree 1.

Sample n rows from the original n rows with replacement. The sample stays the same size, but some rows repeat and others are omitted.

2
Fit one tree to that sample.

Repeated rows effectively get extra weight. At each node, the tree searches candidate splits using its criterion (such as Gini). Random Forest also restricts candidate features at each split.

3
Repeat independently.

Draw a fresh bootstrap sample and fit Tree 2, then Tree 3, and so on. A tree does not correct the previous tree; trees can be trained in parallel.

4
Give every tree the same new input.

Each tree follows its own learned rules and returns a class vote/probability or numeric prediction.

5
Aggregate their contributions.

Classification usually takes the majority vote or averages probabilities. Regression averages the numeric outputs.

ŷRF(x)=1B∑b=1BTb(x)
For regression, each tree Tb predicts a number for the same input x; average B outputs. For classification, the forest combines votes or class probabilities.
Bagging means bootstrap aggregating. It reduces instability by averaging trees trained on different bootstrap samples. Random Forest adds random feature candidates at each split, which helps reduce similarity between trees. Boosting differs: it trains trees sequentially, with later trees correcting the current ensemble.

What does each tree contribute?

A tree contributes one prediction for the case you want to classify or predict. No tree owns a separate part of the answer; all predictions are combined.

Why not make them identical?

If trees make highly correlated errors, averaging helps less. Bootstrap rows and random feature candidates encourage useful diversity while each tree still learns real patterns.

09 · Beyond the basic vote

Out-of-bag estimates & honest evaluation.

Bootstrap sampling leaves some training rows out of each tree’s sample. Those rows can provide a built-in validation estimate.

Why rows are “out of bag”

For a dataset of n rows, a bootstrap sample draws n times with replacement. The chance a particular row is never selected approaches:

(1−1n)n≈e−1≈0.368
About 36.8% of rows are left out of any one tree’s bootstrap sample.

For a row, aggregate predictions only from trees that did not train on it. Compare those OOB predictions with its target.

Evaluation metrics

Classification: accuracy, precision, recall, F1, confusion matrix; use metrics aligned with class imbalance and error cost.

Regression: MAE and RMSE in target units. RMSE penalizes large misses more strongly.

Always compare: a simple baseline, such as majority class or mean target.

MAE=1n∑i=1n|yi−y^i|RMSE=1n∑i=1n(yi−y^i)2
OOB is useful, not magic: it can help monitor generalization, but a final untouched test set is still useful for an unbiased final report, especially after model selection.
10 · Assumptions & validation

Few distribution assumptions. Plenty of data assumptions.

Random Forest does not require a linear feature-target relationship or normally distributed features. But data collection and validation design still matter a lot.

REPRESENTATIVENESS

Will future data look similar?

A random split estimates performance when train and test rows resemble the same population. Distribution shift can break that premise.

DEPENDENCE

Are rows independent?

Repeated patients, users, sites, or households may leak identity. Use group-aware splitting where needed.

TIME

Does time order matter?

For forecasting or temporal prediction, split by time. Do not train on future information and test on the past.

LEAKAGE

Could a feature reveal the answer?

Only use fields available at prediction time. Fit encoders, imputers, feature selection and tuning inside training folds.

A leakage-safe workflow

1
Set aside a final test set.

Choose stratified, group, or time split to match how the model will be used.

2
Tune on training folds only.

Use cross-validation and a task-appropriate metric.

3
Evaluate once on the untouched test set.

Report performance, uncertainty, and important subgroup errors.

Missing values and categorical features need explicit handling depending on the library. Keep preprocessing inside the validation pipeline to prevent leakage.
11 · Interpreting the fit

Feature importance asks: what did the model use?

Importance scores summarize reliance or split utility. They do not tell us what causes the outcome.

MEAN DECREASE IN IMPURITY

Count helpful splits

Sum the impurity reductions attributed to each feature across trees, often weighted by the rows reaching each split.

I(j)=∑tT∑v∈jnodesnvnΔGv

May favor continuous or high-cardinality features with many possible split points.

PERMUTATION IMPORTANCE

Break one feature’s signal

Shuffle a feature in held-out rows. Measure the score drop. A bigger drop suggests predictions depended on that feature.

Imp(j)=Score(X)−Score(Xpermuted(j))

Correlated features can substitute for each other, making each seem less important on its own.

Not causal: if petal length is important to a fitted Iris classifier, that does not prove petal length causes species. The score reflects model behavior and available data.

12 · Bias, variance & practical knobs

Make trees diverse without making them useless.

Averaging helps most when trees are accurate enough individually and make errors that are not too correlated.

Variance intuition

A deep tree can change a lot when training rows change. Averaging many varied trees often reduces that instability.

Var(T¯)=ρ2σ2+1−ρ2Bσ2
Simplified: B trees with variance σ² and pairwise correlation ρ. More trees shrink the uncorrelated part; correlation sets a floor.

Hyperparameters to know

ParameterEffect
n_estimatorsMore trees; often stabilizes until gains taper.
max_depthCaps complexity; shallow trees can reduce overfit.
min_samples_leafLarger leaves smooth predictions.
max_featuresControls randomness and tree correlation.
class_weightCan weight classes differently in classification.

Strengths

Nonlinear patterns, interactions, robust baseline, little need for feature scaling.

Limitations

Less interpretable, larger memory/runtime, importance caveats, no natural extrapolation in regression.

Pruning?

Control growth with max depth/min leaf size; formal pruning is optional and separate from forest randomness.

Practical tuning: start with a reasonable baseline, tune depth / leaf size / max_features using cross-validation, then increase the number of trees until performance stabilizes.

Can you explain the forest now?

Use this one-minute recap to teach the idea back to someone else.

01
A tree partitions examples.

Greedy splits reduce class impurity or regression error; leaves produce predictions.

02
Bootstrap samples make trees see different rows.

Sampling with replacement leaves some examples out of each tree.

03
Feature subsampling makes trees less correlated.

At each split, each tree considers a random candidate subset.

04
Aggregation stabilizes predictions.

Vote for classification; average for regression.

05
Validate the whole workflow.

Use unseen data, prevent leakage, select meaningful metrics, and interpret importance carefully.
