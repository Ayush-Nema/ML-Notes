TP · true positiveModel said positive, and it was. A hit.
FP · false positiveModel said positive, but it was negative. A false alarm (Type I).
FN · false negativeModel said negative, but it was positive. A miss (Type II).
TN · true negativeModel said negative, and it was. A correct rejection.

Read each name right to left: the last word is what the model predicted, the first word says whether that prediction was right.

"Prevalence-independent" means the value stays the same if you run the same classifier on a population with a different share of positives. Those are the ones to compare across sites or datasets.

    How the averages differ

    Macro: plain mean over classes, so a rare class counts as much as a common one. Use it when every class matters. Weighted: mean weighted by class support, so it tracks the common classes. Micro: pool all TP, FP and FN first, then compute. For single-label problems micro precision, recall and F1 all equal accuracy. Undefined per-class values (zero denominator) count as 0 in the averages, which matches scikit-learn's default.

    Choosing a metric

    No metric is best in general. Pick the one that matches what a mistake costs you, then report a few that cover each other's blind spots.

    SituationReach forBe careful with
    Balanced classes, similar error costsAccuracy, macro-F1, MCCHiding per-class weaknesses; still report per-class recall
    Positives are rare and you must find themRecall, precision, F-β, PR-AUC (average precision)Accuracy and ROC-AUC on their own: both can look excellent
    False alarms are expensive (auto-blocking, limited review capacity)Precision, specificity, recall at a fixed FPRRecall alone
    Misses are expensive (screening, safety)Recall (sensitivity), NPV, F2Precision alone
    Ranking quality, threshold not chosen yetROC-AUC (balanced data), PR-AUC (imbalanced data)Reading AUC as accuracy; comparing PR-AUC across datasets with different prevalence
    You need trustworthy probabilitiesLog loss, Brier score, reliability diagram, ECEAUC, which ignores calibration completely
    One number for a 2×2 under imbalanceMCC, balanced accuracy, Cohen's κF1: ignores TN and depends on which class is "positive"
    Comparing sites or datasets with different prevalenceRecall, specificity, LR+, LR−, Youden's JPrecision, accuracy, F1: they move with prevalence
    Multi-class with rare classesMacro-F1, per-class recall, the confusion matrix itselfMicro-F1 or accuracy alone: dominated by large classes

    Traps worth knowing

    1. Accuracy paradox. With 5% positives, a model that never predicts positive scores 95% accuracy. Load "Always predicts negative" above to see it.
    2. Base-rate fallacy. A test with 90% recall and 95% specificity sounds strong, yet at 1% prevalence most of its positive calls are false. Use the prevalence slider to check.
    3. 0.5 is a default, not a property of the model. The best threshold depends on costs and prevalence. Choose it on validation data, never on the test set.
    4. F1 is not symmetric. It ignores TN, so swapping the positive class changes it. Choose the positive class deliberately.
    5. ROC can flatter imbalanced problems. FPR divides by a huge negative count, so thousands of false alarms can still give a tiny FPR. Check the precision-recall curve too.
    6. Small samples are noisy. With 20 positives, an observed recall of 0.90 has a 95% Wilson interval of roughly 0.70 to 0.97. The cards above show these intervals for simple proportions.
    7. Metrics describe the test distribution only. Leakage, duplicates and dataset shift make any number optimistic for deployment.

    scikit-learn equivalents

    Every metric on this page in a few lines of Python. Confirm against your installed version's documentation, as signatures occasionally change.

    from sklearn.metrics import (
    confusion_matrix, accuracy_score, precision_score, recall_score, f1_score,
    fbeta_score, balanced_accuracy_score, matthews_corrcoef, cohen_kappa_score,
    jaccard_score, roc_auc_score, average_precision_score, log_loss,
    brier_score_loss, class_likelihood_ratios, classification_report,
    roc_curve, precision_recall_curve,
)
from sklearn.calibration import calibration_curve

# y_true: 0/1 labels, y_pred: 0/1 predictions, y_prob: predicted P(y=1)
tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel()   # rows = actual, cols = predicted

accuracy     = accuracy_score(y_true, y_pred)
precision    = precision_score(y_true, y_pred)                 # PPV
recall       = recall_score(y_true, y_pred)                    # sensitivity, TPR
specificity  = recall_score(y_true, y_pred, pos_label=0)       # TNR
npv          = precision_score(y_true, y_pred, pos_label=0)
f1           = f1_score(y_true, y_pred)
f2           = fbeta_score(y_true, y_pred, beta=2)
bal_acc      = balanced_accuracy_score(y_true, y_pred)
mcc          = matthews_corrcoef(y_true, y_pred)
kappa        = cohen_kappa_score(y_true, y_pred)
jaccard      = jaccard_score(y_true, y_pred)
lr_pos, lr_neg = class_likelihood_ratios(y_true, y_pred)       # scikit-learn >= 1.2

# threshold-free, use scores or probabilities
roc_auc      = roc_auc_score(y_true, y_prob)
pr_auc       = average_precision_score(y_true, y_prob)
ll           = log_loss(y_true, y_prob)
brier        = brier_score_loss(y_true, y_prob)
frac_pos, mean_pred = calibration_curve(y_true, y_prob, n_bins=10)

# multi-class: choose the average explicitly
f1_macro     = f1_score(y_true, y_pred, average="macro")
f1_weighted  = f1_score(y_true, y_pred, average="weighted")
f1_micro     = f1_score(y_true, y_pred, average="micro")        # equals accuracy
print(classification_report(y_true, y_pred, digits=3))
