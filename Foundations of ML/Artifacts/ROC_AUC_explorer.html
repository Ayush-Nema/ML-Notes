Logistic regression / From probability to decision

First, predict a probability.

Logistic regression combines input features into a linear score z = b + w₁x₁ + …, then uses an S-shaped sigmoid to produce a probability of spam. Here, one synthetic evidence feature x gives z = (x − 50) / 12. Higher evidence means a larger probability.

p(spam) = 1 / (1 + exp(−z))

Then, make a decision.

If p ≥ threshold, predict spam. At 0.50, p = 0.74 is spam and p = 0.32 is legitimate. Raise the threshold to demand stronger evidence; lower it to flag more emails.

Moving the threshold does not retrain the model. The sigmoid and probabilities stay fixed; the predictions change.

02 / The language, made simple

What do these terms actually mean?

“Positive” means the class we want to detect—spam in this example. It does not mean something good.

Score & threshold

A score orders emails from less to more spam-like. The threshold converts that score into a yes/no decision. At 0.50, a score of 0.74 is flagged; 0.32 is left alone.

TPR · Recall · Sensitivity

Of all the actual spam, how much did we catch? Catching 4 of 6 spam emails gives a TPR of 66.7%.

TPR = TP / (TP + FN)

FPR · False alarm rate

Of all the legitimate mail, how much did we flag by mistake? Flagging 2 of 6 legitimate emails gives an FPR of 33.3%.

FPR = FP / (FP + TN)

ROC · Receiver Operating Characteristic

A plot of TPR against FPR as the threshold moves through every possible decision point. Curves closer to the top-left corner generally indicate better ranking.

AUC · Area Under the ROC Curve

A single number summarizing the full ROC curve. It measures how well the scores rank positive examples above negative ones across thresholds.

AUC ranges from 0 to 1

FPR is different from precision

FPR asks about all legitimate mail. Precision asks about the mail we flagged: how much was actually spam? Always check the denominator.

Precision = TP / (TP + FP)

AUC of 0.80 does not mean 80% accuracy. It means about 80% pairwise ranking success (with half-credit for ties). Changing the threshold changes the decisions and the highlighted point, but leaves AUC unchanged.

For each model, choose its own threshold to catch the most spam without exceeding this FPR. Small datasets have coarse steps, so the chosen FPR can be below your budget. Table thresholds are rounded; “Above 1” means flag nothing. This budget is independent of the main threshold slider.

Logistic regression

Learns a smooth sigmoid probability from the evidence feature. It assumes the log-odds change linearly with that feature.

Decision tree

Splits the feature into ranges and assigns each range a spam proportion. Many emails receive the same score, creating ties and larger ROC steps.

Gaussian naive Bayes

Models a bell-shaped feature distribution within each class, then uses Bayes’ rule to estimate spam probability. With one feature, there is no multi-feature independence assumption to test.

K-nearest neighbors (KNN)

Looks at the 15 closest training emails and uses their spam fraction as the score. Local patterns and ties can change the ranking.

Read AUC as ranking ability

If model A has AUC 0.90 and B has 0.75 on the same evaluation set, A has better overall pairwise ranking. Those are illustrative numbers, not fixed scores for any algorithm.

Best overall vs. best for your budget

ROC curves can cross. A model with a lower total AUC can still catch more spam in the low-FPR region you care about. Move the budget slider and compare the TPR column.

Same AUC can mean different scores

Models can assign different probabilities while ordering every email the same way. They then have the same ROC curve and AUC. AUC does not measure probability calibration.

A fair teaching comparison. All four models are fitted once on the same 240 separately generated synthetic training emails, using one evidence feature. The selected 12 or 60 emails are used only for evaluation. Simple is a hand-picked worked example; Realistic is a fixed noisy synthetic sample. No model receives evaluation labels when predicting. Model and threshold selection in practice use validation data; final performance is measured on an untouched test set, with uncertainty assessed.
