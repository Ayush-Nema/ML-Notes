SUBTOPIC 1

What is a hyperparameter?

When a model trains, it learns some numbers by itself from data. These are the parameters (for example, the weights in a neural network). But there are other numbers that you must choose before training starts. Those are the hyperparameters.

🍞 Baking analogy: The bread itself (its texture, how it rises) is what gets "learned" while baking. The oven temperature, the baking time and the amount of yeast are settings you choose beforehand. Pick them badly and even the best recipe gives bad bread. Hyperparameter tuning = finding good oven settings.

Learning rate: how big is each step?

Most models learn by gradient descent: look at the slope of the error, then take a step downhill. The learning rate controls the size of that step.

⛰️ Imagine walking down a foggy valley to reach the lowest point. Tiny steps are safe but take forever. Giant leaps may carry you right over the bottom to the other side.

SUBTOPIC 3

Model complexity: underfitting vs overfitting

Many models have a "how flexible am I?" hyperparameter: the degree of a polynomial, the depth of a tree, the number of layers in a network. More flexibility lets a model capture more patterns, but it can also start memorising noise.

📚 A student who memorises last year's exam answers word for word (overfitting) fails when the questions change. A student who only learns "everything is about 50%" (underfitting) never gets it right either. We want the student who understands the idea.

Regularization: putting a leash on the model

Regularization adds a penalty for extreme, wiggly solutions. Its strength is a hyperparameter, often called λ (lambda) or alpha. A small λ means little restraint; a large λ forces the model to stay very simple.

🐕 A dog on a leash. No leash (λ = 0) and it runs wild chasing every squirrel (noise). A leash that is too short and it can't move at all. A medium leash keeps it well behaved but still lets it explore.

Search strategies: grid vs random

With many hyperparameters, we have to try combinations and see which scores best. Two classic strategies:

  • Grid search: try every combination on an evenly spaced grid.
  • Random search: pick combinations at random.

Usually some hyperparameters matter much more than others. A grid wastes trials by repeating the same few values of the important one; random search tries a new value each time.

SUBTOPIC 6

Validation & cross-validation: judging fairly

To compare hyperparameter choices we need an honest score. We never judge a model on the data it trained on. We split the data:

  • Training set: the model learns from this.
  • Validation set: we compare hyperparameters using this.
  • Test set: locked away until the very end for one final, honest check.

With little data, one validation split can be lucky or unlucky. K-fold cross-validation splits the data into K parts, and each part takes a turn as the validation set. Then we average the K scores.

SUBTOPIC 7 · PRACTICAL EXAMPLE

Putting it together: tuning k in K-Nearest Neighbors

K-Nearest Neighbors (KNN) is one of the simplest models: to classify a new point, look at its k closest training points and let them vote. There is nothing to "learn" except which points to remember, and the one big decision you make is the hyperparameter k. That makes it a perfect, realistic playground for everything above.

🏘️ You move to a new neighborhood and wonder if the locals like pizza or sushi. Asking only your 1 nearest neighbor is risky (one odd person misleads you). Asking the whole city ignores what your street is like. Asking your nearest 10 or so is usually just right.

The workflow we will follow

  1. Split the data: 120 training, 60 validation and 60 test points. The test set stays locked.
  2. Try different values of k (1 to 40) and score each one.
  3. Compare scores on validation data and with 5-fold cross-validation (using the training data only).
  4. Pick the best k, then unlock the test set once for an honest final score.

What you saw, in plain words

  • Very small k (like 1): the boundary is jagged and wraps around single noisy points. Training accuracy is a perfect 100% because every training point is its own nearest neighbor, but validation accuracy is lower. This is overfitting.
  • Very large k: the boundary becomes smooth and blunt, and local structure gets averaged away. Both training and validation accuracy drop. This is underfitting.
  • In between: validation and CV accuracy peak. That is the k you want.

The same thing in real code (scikit-learn)

# 1) Split: hold the test set out first
from sklearn.model_selection import train_test_split, GridSearchCV
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=0, stratify=y)

# 2) Scale features (KNN uses distances, so units matter!)
pipe = make_pipeline(StandardScaler(), KNeighborsClassifier())

# 3) Try k = 1..40 with 5-fold cross-validation on the training data
search = GridSearchCV(pipe,
    param_grid={"kneighborsclassifier__n_neighbors": range(1, 41)},
    cv=5)
search.fit(X_train, y_train)

print("Best k:", search.best_params_)
print("CV accuracy:", search.best_score_)

# 4) One final, honest check on the locked test set
print("Test accuracy:", search.score(X_test, y_test))

Practical tips for KNN tuning

  • Scale your features. If one feature is "income in dollars" and another is "age in years", income will dominate all distances. Standardize first.
  • Use an odd k for two-class problems to avoid tied votes.
  • A common starting range is 1 up to about √(number of training samples), then refine.
  • Other KNN hyperparameters worth tuning: the distance metric (Euclidean, Manhattan) and whether closer neighbors get more voting weight.
  • If several k values tie, prefer the larger k: it gives a simpler, more stable model.

A simple recipe

  1. Split your data into train / validation / test. Lock the test set away.
  2. Choose which hyperparameters to tune and sensible ranges (use a log scale for things like learning rate and λ).
  3. Try values with random search (or smarter tools such as Bayesian optimization) and score with validation or cross-validation.
  4. Pick the best setting, retrain, and evaluate once on the test set.
