A model, in plain language

A model is a rule learned from data. For example: use home size and location to predict a house price. Training adjusts that rule using known examples.

When should I avoid a random split?

For forecasting, train on the past and validate on later periods. If several rows belong to the same person, customer, or device, keep that group in one split. For classification with independent examples, stratification can preserve class proportions.

04 / The balancing act

Flexibility helps.
Until it hurts.

Bias is the error from an overly simple view of the world. Variance is how much a model changes when its training sample changes.

High bias → misses the pattern

Like using “all shoes are size 8” to fit everyone. Consistent, but often wrong.

High variance → chases the sample

Like designing a sizing rule around the last few people who entered the shop. A different group changes the rule.

Find a useful level of complexity

An illustrative trend, not measured results from the previous activity. Real curves are usually noisier.

Training errorValidation errorSelected complexity

Simple models tend to have more bias and less variance; complex models tend to have less bias and more variance. Some uncertainty is unavoidable: noisy measurements and missing information cannot be fixed by complexity alone.

05 / More than one rehearsal

Give every fold
a turn in the spotlight.

One validation split can be lucky or unlucky. Cross-validation repeats training and evaluation on different splits to give a broader view.

K-fold cross-validation, step by step

Keep the final test set sealed. Divide the remaining development data into K folds. Train a fresh model on K−1 folds, validate on the remaining fold, and rotate.

Scores are computed on 60 simulated development examples with a degree-3 model. Each equal-sized fold contributes equally to the mean. Every example is validated once per full K-fold run; each fold gets a newly fitted model. The final test set is never used here.

How to choose: compare candidate settings by their mean cross-validation score using the same folds. Then refit the chosen setup on all development data and evaluate on the untouched test set. More folds cost more training; 5 or 10 are common starting points.
Is ordinary K-fold always appropriate?

No. Use stratified folds to help preserve class proportions for independent classification examples, group-aware folds for repeated entities, and forward-in-time evaluation for forecasting. Any preprocessing must be fitted separately inside each training fold.

THE HIDDEN TRAP

Data leakage: an accidental peek at the answers

Leakage happens when information unavailable at prediction time influences training or model selection. Your score looks better than real-world performance.

Show the safe workflow

Split first. Fit imputation, scaling, feature selection, and other learned preprocessing using only the training set. Apply those fitted steps to validation data. During cross-validation, fit the entire pipeline anew inside each training fold. Keep duplicates and related entities out of both sides of a split.

Also check timing: a “refund issued” field is not a valid input for predicting a return before a customer buys an item.

Your validation checklist

  • 1. Define the real prediction task.What will be known at prediction time? Which future cases matter?
  • 2. Pick a meaningful metric before comparing.MSE can work for numeric predictions. For rare-event classification, accuracy alone can hide missed positives; consider precision and recall.
  • 3. Choose a split that matches reality.Respect time, groups, and class balance. Seal the test set early.
  • 4. Fit preprocessing inside training only.Repeat this rule in every cross-validation fold.
  • 5. Compare fairly and check stability.Use the same splits and metric. Inspect fold variation, learning curves, and important subgroups. Repeated validation tuning can itself overfit.
  • 6. Refit, test once, then monitor.Refit the chosen pipeline on development data; report the final test score with its limitations. New conditions can still change performance.

Final knowledge check

Your takeaway

A low training error tells you a model learned its examples. Reliable performance on properly held-out data tells you whether it may be useful on new ones.

Start with a realistic split, compare models using validation or cross-validation, and keep the final test set sealed until your choices are complete.
